claude-setup downloads about 90 MB, adapts it for iOS and signs it. A Claude subscription or an Anthropic account is required. For a newer release just run sudo claude-setup again.

Was daran neu ist

What is new about this

Anthropic liefert Claude Code seit Fassung 2.1.113 nicht mehr als JavaScript, sondern als mit Bun übersetztes Binary für macOS. Bisherige Portierungen auf iOS hängen deshalb bei Fassung 2.1.19 fest und bringen ein eigenes Node mit.

Since version 2.1.113 Anthropic no longer ships Claude Code as JavaScript but as a Bun-compiled binary for macOS. Existing iOS ports are therefore stuck at 2.1.19 and carry their own Node build.

Dieses Paket geht den anderen Weg: es lädt beim Einrichten das aktuelle macOS-Binary und rechnet es auf dem Gerät auf iOS um. Du bekommst also die Fassung, die gerade auch auf dem Rechner läuft.

This package takes the other route: at setup time it downloads the current macOS binary and converts it for iOS on the device. You get the version that is current on the desktop right now.

Was dafür nötig war

What it took

Das macOS-Binary hängt an genau vier Dingen, die es unter iOS nicht gibt.

The macOS binary depends on exactly four things iOS does not provide.

Drei fehlende Symbole

Three missing symbols

Von 842 undefinierten Symbolen fehlen unter iOS genau drei: __clear_cache, pthread_jit_write_protect_np und posix_spawn_file_actions_addfchdir. Eine Ersatzbibliothek liefert sie nach und reicht alles Übrige an die echte libSystem weiter; im Binary wird nur der Ladepfad umgebogen — beide Pfade sind zufällig genau 26 Zeichen lang, es verschiebt sich also kein Byte.

Of 842 undefined symbols exactly three are missing on iOS: __clear_cache, pthread_jit_write_protect_np and posix_spawn_file_actions_addfchdir. A replacement library supplies them and re-exports everything else to the real libSystem; inside the binary only the load path changes — both paths happen to be exactly 26 characters, so nothing shifts.

SharedArrayBuffer kann es unter iOS nicht geben

SharedArrayBuffer cannot exist on iOS

JavaScriptCore blendet ihn aus, solange die Gigacage fehlt — und die will 64 GB Adressraum reservieren. Am Gerät nachgemessen: iOS gibt einem Prozess rund 9 GB, darüber scheitert jedes mmap. Also wird jede eifrige Verwendung im Binary auf ArrayBuffer umgeschrieben und mit Leerzeichen auf dieselbe Länge gebracht. Stellen, die ohnehin mit typeof abgesichert sind, bleiben unangetastet.

JavaScriptCore hides it while the gigacage is unavailable — and that reservation is 64 GB. Measured on the device: iOS grants a process about 9 GB, past which every mmap fails. So every eager use in the binary is rewritten to ArrayBuffer and padded with spaces to the same length. Places already guarded by typeof are left alone.

Skripte lassen sich nicht starten

Shell scripts cannot be spawned

posix_spawn auf ein #!-Skript liefert unter iOS EPERM — auch aus unverändertem Node heraus. Claude Code ruft aber security für den Schlüsselbund und open für den Browser auf, und beides bringt iOS nicht mit. Beide Ersätze sind deshalb übersetzte Programme, keine Skripte. Ohne den ersten wird das Anmeldetoken stillschweigend nicht gespeichert.

posix_spawn on a #! script returns EPERM on iOS — even from an unmodified Node. But Claude Code calls security for the keychain and open for the browser, and iOS ships neither. Both replacements are therefore compiled programs, not scripts. Without the first, the sign-in token is silently never stored.

Zwei Framework-Pfade

Two framework paths

Bun öffnet …/Versions/A/CoreFoundation; unter iOS liegen die Frameworks flach. Ohne die Korrektur bricht es mit Cannot Load CoreFoundation ab. iOS' CoreServices exportiert die FSEvents-Funktionen übrigens wirklich — der Dateiwächter läuft.

Bun opens …/Versions/A/CoreFoundation; on iOS the frameworks are flat. Without the fix it aborts with Cannot Load CoreFoundation. iOS' CoreServices does export the FSEvents functions, by the way — the file watcher works.

Was du wissen solltest

Worth knowing

Platz. Nach dem Einrichten liegen rund 300 MB unter /var/jb/usr/local/lib/claude-code. Das Paket selbst ist 16 KB.

Space. After setup about 300 MB sit in /var/jb/usr/local/lib/claude-code. The package itself is 16 KB.

Das Token liegt im Klartext. iOS hat keinen Schlüsselbund, den ein fremder Prozess benutzen kann. Das Anmeldetoken landet deshalb in einer Datei mit Modus 0600 unter ~/.claude/keychain.

The token sits on disk. iOS has no keychain a third-party process can use, so the sign-in token goes into a file with mode 0600 under ~/.claude/keychain.

Als root. Läuft claude als root, ist --dangerously-skip-permissions freigeschaltet — Claude arbeitet dann ohne Rückfrage und kann alles auf dem Gerät ändern. Ohne den Schalter wird wie gewohnt vor jedem Werkzeug gefragt.

As root. When claude runs as root, --dangerously-skip-permissions is unlocked — Claude then works without asking and can change anything on the device. Without the flag it asks before each tool as usual.

Aktualisieren. Der eingebaute Autoupdater ist abgeschaltet; er würde das umgerechnete Binary durch das macOS-Build ersetzen. Für eine neuere Fassung sudo claude-setup.

Updates. The built-in auto-updater is off; it would replace the converted binary with the macOS build. For a newer release run sudo claude-setup.
